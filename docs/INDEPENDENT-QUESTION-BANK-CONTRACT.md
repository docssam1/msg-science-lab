# MSG 초·과·심 독립 문제은행 · 범위 계약

상태: `work: pending` · `evidence: draft` · `release: locked` (2026-10-03). 이 문서는 독립 문제은행의 설계 경계를 기록할 뿐, 문항이나 서비스를 구현·출시했다는 뜻이 아니다.

## 서로 다른 두 제품

| 구분 | 교재 테스트 연계 워크지(현재 1·2차시 구현 범위) | 독립 문제은행(미구현) |
| --- | --- | --- |
| 시작 | 해당 차시 Daily Test의 첫 시도·오개념 진단 뒤 | 교재 테스트를 치르지 않아도 별도 입구에서 |
| 문항 선택 | 진단 개념에 맞는 유사문제, 별도 심화 미니세트 | 단원·개념·유형·난도·학습 목적을 사용자가 선택 |
| 출력 | 배정된 미풀이 문항의 답 없는 A4 워크지 | 조건에 따라 새 문제지·교사용 정답지 구성(설계 대상) |
| 기록 | 테스트·워크지의 첫 시도 및 셀프 체크 | 별도의 문제지 발행·풀이·검수 기록(설계 대상) |
| 현재 상태 | 제한된 고정 문항과 인쇄 연결을 검수 중 | 문항 데이터·선택 화면·인쇄·채점 모두 없음 |

내부 코드의 `bank` 변수명, `remedy-bank.js`와 `advanced-bank.js` 파일명은 현재 워크지용 문항 풀의 역사적 이름이다. 이를 독립 문제은행이 존재한다는 표시로 해석하지 않는다. `unit-assessment-index.js`는 원본 PART I 단원평가 20문항의 잠긴 출처 색인일 뿐, 독립 문제은행의 문항 목록이 아니다.

## 독립 문제은행을 만들 때 필요한 승인·검증

1. 원장 승인으로 대상 범위(초과심_물리 PART I 전체인지, 1·2차시 시범인지), 대상 학년, 공개·인쇄 권한과 정답 공개 시점을 먼저 확정한다.
2. 원본 교재 문항, 창작 문항, 테스트 연계 워크지 문항을 서로 다른 ID·출처·권리 상태로 관리한다. 원본 PDF나 정답을 공개 저장소에 통째로 복사하지 않는다.
3. 각 문항에 단원·개념·유형·난도·필요한 그림·답 계약·오개념·검수 상태·출처 위치·변형 키를 둔다. 여러 고정 유형을 섞어 뽑더라도 이미 사용한 동일 변형은 다시 선택하지 않는다.
4. 학생 문제지와 교사용 정답·해설은 별도 출력으로 만들고, 첫 답 전 정답이 학생 화면·인쇄본에 드러나지 않도록 한다. 서술형은 별도 승인된 루브릭과 학생 확인 절차 전까지 자동 채점하지 않는다.
5. `learner_stage`와 `learner-fit`(language, representations, prerequisites, reasoning-load, response-mode), 원본 대조, 답의 유일성/루브릭, 실제 A4·태블릿·PC, 개인정보·저작권 관문이 통과하기 전에는 release를 `locked`로 둔다.

다음 구현의 첫 산출물은 독립 문제은행의 상세 작업 계획과 1개 단원·여러 유형의 검수용 시범 세트다. 현재 워크지 문항을 이름만 바꿔 옮기거나 기존 20문항 색인을 출시 문항 수로 계산하지 않는다.
